# ltrp-sim 借用改造计划（五项功能移植）

从 `lunar-lava-tube-routing-sim-main` 移植五项能力到 `ltrp-sim`，不改变其去中心化根本逻辑：所有新物理量（SNR/BER/温度/积压）仍由节点本地计算或经信标携带，路由仍是分布式 DSDV，引擎不做全局路由计算。

**已定方向**：单频段（校准 UWB profile）；热浪灾难改为温度浪潮（物理耦合）；参数滑块做全局协议参数 + 节点物理参数两层。

## 1. 新建 `ltrp-sim/backend/sim/physics.py`（移植+校准）

从源项目 `physics.py` 移植并适配为米制单位（ltrp-sim 无 WORLD_SCALE）：

- `BAND_PROFILE`：单频段 UWB，但带宽从 500MHz 校准到 **20MHz**（否则 260m 间距下 kTB 噪声底过高、链路算不平），`PATH_LOSS_EXPONENT=2.6` 保留
- `free_space_path_loss_db(d_m, freq_ghz)`：照搬
- `thermal_noise_floor_dbm(node, bw)`：照搬（kTB + 接收机 6dB NF，用接收方温度）
- `link_budget(tx, rx) -> {snr_db, ber, margin_db, up}`：照搬主体（倾角失配惩罚、BPSK BER via erfc、`up = margin>0 and ber<1e-3`），去掉 LoRa 分支和 band 参数
- `_damage_prob(ber, nbytes) = 1-(1-ber)^(8n)`：照搬（供数据面掷骰）
- **校准目标**：默认参数（tx_power 14dBm、双端增益 3dBi）下，d ≤ 0.8×RANGE(260m) 链路闭合有余量、d→RANGE 临界、+50°C 时噪声系数恶化（0.12dB/°C）足以熔断边缘链路。若 20MHz 仍不平，调 tx_power/增益基准值，不引入第二频段

## 2. `nodes.py`：物理能量/辐射模型（保持 soc 状态机不变）

`soc`（0-100%）仍是协议唯一能量状态源（PROTECTED/DYING 状态机、睡眠调度、DLER 度量全部不动），其下垫真实电池模型：

- 新字段：`battery_mah/battery_capacity`（12000mAh）、`i_tx/i_rx/i_sleep`、`temp_c`（默认 −20）、`radiation_rad`、`seu_flips`、`supercap_pct`、`tx_power_dbm/rx_sensitivity_dbm/ant_gain_dbi/tilt_deg`
- `thermal_derating` 属性：照搬（>45°C 与 <-20°C 降额）
- `effective_rx_sensitivity()`：照搬（热噪声底 + 门限 8dB + 高温 NF 恶化 0.12dB/°C + 老化偏置）
- `energy_step(dt)`：改用 mAh 记账——`avg_current × dt × 睡眠系数(0.15) / thermal_derating` − RTG 涓流（速率调低至"忙节点净耗、休眠节点净回升"，保证 PROTECTED/DYING 仍会触发），然后 `soc = battery_mah/capacity × 100`，状态机逻辑原样保留；温度随机游走 ±0.15°C
- `spend(amount)`：换算为 mAh 扣减（经 capacity），热浪不再 ×5（由热降额自然放大）
- **SEU**：每拍 `p = min(0.02, radiation/50000)` 掷骰；触发时 `seu_flips+=1`、**清空邻居表**（节点被迫重新发现邻居——去中心化语义下比源项目的 SEU_RESET 状态更有意义，恢复由信标自然完成），发事件
- `MUTABLE` 白名单 + `apply_override(key, value)`：照搬模式，白名单 = `temp_c, tx_power_dbm, rx_sensitivity_dbm, ant_gain_dbi, tilt_deg, battery_mah, radiation_rad, i_tx, supercap_pct`

## 3. `protocol.py`：可调参数 + 质量感知链路代价 + 信标携带积压

- **全局参数**：模块级 `class Params` 实例 `PARAMS`（属性 `tb, gamma, alpha, e_die, q_cap, hops_max, pkt_ttl`，初值=现常量），带白名单+范围校验的 `set_param(key, value)`；`expire_neighbors/link_cost/dsndv_relax` 及 engine 中的常量读取全部改为 `PARAMS.xxx`（数值与默认行为完全不变）
- **`link_cost(a, b, snr=None, tx_load=0, rx_load=0)`**：在 DLER 基础上（12.0 + d/40 + ALPHA）增加两项：
  - 链路质量项（源项目式）：`snr<15 时 (15-snr)×0.25 + min(3.0, ber×3000)`
  - 拥塞项（分布式 ACO）：`(tx_load + rx_load)×权重`，load 来自信标
  - 量级控制在原成本同数量级，`MAX_COST=3000` 语义不变
- **`compose_hello`**：增加 `"bl": len(n.bundles)+len(n.packets)`（积压）字段；**`on_hello`**：存入邻居条目并 EWMA 平滑 `e["load"] = 0.8×旧 + 0.2×新`（分布式信息素），同时存 `e["ber"]`（供数据面掷骰）
- `dsdv_relax`：调用升级后的 `link_cost`，传入 `e["snr"]/e["load"]` 与本节点积压——**仍是每节点本地松弛，逻辑零改动**

## 4. `engine.py`：接线（改动最多，逐点列出）

- `_snr(a,b)` → 调 `physics.link_budget`：对 adj 候选对计算物理 SNR（+±2.5dB 抖动保留），BER/余量随邻居条目存储；链路建立门限改为 `EWMA SNR ≥ PARAMS.gamma 且 link_budget.up`（GAMMA 默认 12dB 不变，正常情况下行为与现在一致）
- **热浪灾难重定义**：`heat` = 温度浪潮——激活期间各节点 `temp_c` 抬升目标 +50°C（结束后缓慢回落），链路恶化走 NF/噪声底耦合，耗电走热降额；删除硬编码 −6dB/×5
- **`_traffic()` 逐跳损伤与重传**（源项目 transport.py 机制的最小移植）：
  - `_mk_pkt` 增加 `bytes`（遥测 256B，关键控制 128B）、`retries=0`
  - 每跳发送时：`p = _damage_prob(ber, bytes)` 掷数据骰 + 14B ACK 骰；失败则 `retries+=1`、报文留在本节点下一拍重发同一跳；`retries > 3` → 丢弃（`lost+=1`，发 `msg_fail` 类事件）
  - 成功路径（TTL/环路防护/毒化路由/束化）全部不动；stats 增加 `retries`、`damaged_drops`
- `apply_override(node_id, params)`：照搬源项目引擎层（含温度 ≥100°C 烧毁裁决与叙述事件）；`set_global_param(key, value)`：写 `PARAMS` 并广播新参数
- `init_payload`/`snapshot()`：`params` 字段改为读 `PARAMS`；节点字典增加 `temp/seu/retries`，`nbrs` 扩展为 `[id, snr, ber]`；stats 增加 `retries/damaged_drops`
- SEU 触发时发 `seu` 事件（沿用现有事件机制）

## 5. `main.py`：一个新端点

- `POST /action/param`：body `{"node": "S-05", "params": {...}}` → 节点覆写；body `{"params": {"tb": 1.8}}` → 全局协议参数。校验失败返回 `{"ok": false, "error": ...}`。不触发即时重算/广播（引擎 0.3s 周期自然生效，避免滑块拖动风暴）

## 6. 前端（React/Canvas，沿用 REST `api()` 模式）

- **`Inspector.jsx`**：移植源项目 `NodeInspector` 的滑块机制——`PARAM_GROUPS` 分组定义（能源/射频/环境三组 8 个滑块 + 辐射）、`pending` 本地回显、120ms 尾值节流 `push`、快照自动同步（每 0.3s 刷新未拖动的键）；`onSetParam` → `api("/action/param", {node, params})`；现有展示行（路由/邻居/束）保留，邻居行加 BER
- **新组件 `ParamsPanel.jsx`**：全局协议参数面板（tb/gamma/alpha/e_die/q_cap/hops_max/pkt_ttl 滑块，范围含默认值标注），HUD 加"参数"按钮开合；同步读 `snapshot.params`
- **`HUD.jsx`**：stats 增加热浪（温度浪潮）期间显示、重传/损伤丢包 chip
- **`TopoMap2D.jsx`**：tooltip 节点信息加温度/SEU 次数，邻居格加 BER 显示（`nbrs[2]`）
- **`App.css`**：滑块与面板样式
- `ws.js` 无需改动（REST 走 `api()`）

## 7. 验证

1. `python -c "import sim.engine"` 及后端启动无报错
2. 默认参数下对比改造前后：链路建立数、覆盖率、投递率应基本一致（校准目标）
3. 逐项手测：拖 T_B 滑块看信标节奏变化；拖节点温度滑块到 80°C 看链路熔断与重路由；热浪灾难看温度→掉链→换路闭环；SEU 清邻居表后自愈；低信噪比链路上观察重传统计
4. 前端 `npm run build` 通过 + 浏览器实测滑块 120ms 节流与快照回显

## 不做的事

- 不引入双频段/信道分配（RCSPA）、不移植区块链层、不做 Dijkstra 波前动画
- 不改变：DSDV 分布式松弛、割点检测、自愈移动、DTN 摆渡、睡眠调度、快照/事件协议格式主体
- `lunar-lava-tube-routing-sim-main` 项目本身零改动（只读源）
