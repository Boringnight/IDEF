# 复杂熔岩管结构下的去中心化路由通信保持算法设计

> 版本:v1.0(2026-09-02)
> 定位:接续开题报告"自组织、自愈、懂硬件"的三关键词,把现有仿真沙盘的全局 Dijkstra"上帝视角"升级为**真正的去中心化协议**。
> 三篇核心文献:路艳玲《面向月球探测多机器人通信系统的Ad_hoc路由协议优化设计》、徐双《空间延迟/中断容忍网络的接触图路由研究综述》、李勐《多智能体强化学习赋能空间无人系统》。

---

## 1. 问题定义:复杂结构带来什么新困难

开题阶段假设的是单一管道 + 巨石遮挡。真实熔岩管是**多腔室 + 窄喉道 + 蜿蜒分支 + 天窗竖井**的复合结构,对通信网的冲击集中在四点:

| 结构特征 | 通信后果 |
|---|---|
| 多腔室,仅窄喉道连通 | 拓扑出现**割点/割边**(一座喉道中继挂掉,整腔失联),图不再是"密集 mesh"而是"串珠状" |
| 腔室间无视距 | 域间链路稀少且质量差,单条链路承担全部跨域流量,**排队与容量成为瓶颈** |
| 巨石/塌方动态变化 | 链路"看得到却连不上",SNR 波动大,静态路由表迅速过时 |
| 月球车按勘察计划移动 | 连接**间歇但有规律**——车在 A、B 腔之间周期巡逻,构成天然的"接触窗口" |

同时保留原有约束:无基站无中心、道钉电池供电、急停/转向指令要求实时、节点损坏是常态。

**核心矛盾:结构越复杂,越需要全局信息来做路由;但熔岩管里恰恰没有全局信息(没有中心、链路间歇、节点会坏)。**

## 2. 三篇文献的可迁移思想

| 文献 | 核心思想 | 迁移到熔岩管 |
|---|---|---|
| 路艳玲 DLER | 路由度量 = 跳数 + 总发射功率 + 路径最小剩余能量;能量低于阈值 E_min 的节点被保护;分布式 Bellman-Ford 求解,DSR 源路由保障实时指令 | **能量状态机式度量切换**直接可用;分布式 Bellman-Ford 是去中心化的计算骨架 |
| 徐双 CGR 综述 | 连接的"可预知性"是资源:接触计划(谁、何时、速率多少)→ 本地建接触图 → 逐跳重算;存储-携带-转发容忍中断;改进方向:最早到达时刻(防环)、路径编码/缓存(降开销)、超额预订管理、接触异常处理 | 熔岩管里的"可预知性"来自**勘测地图 + 车辆巡逻计划 + 道钉唤醒表 + 地球可见窗口**——这就是月面版的接触计划;CGR 节点失效时数据包堆积的教训(综述 4.3 节)必须用**主动故障检测 + 毒化重算**来规避 |
| 李勐 MARL | CTDE(中心化训练、去中心化执行):QMIX 值分解保证个体贪婪 = 全局最优;Dec-POMDP 建模局部观测;数字孪生里训练、在轨部署;分层强化学习 + 元学习应对非平稳 | 仿真沙盘本身就是天然**数字孪生训练环境**;但安全上采用"**协议兜底、学习调参**"的分层架构,防止学坏 |

## 3. 总体架构:LTRP(Lava-Tube Routing-Preserving Protocol)

三层解耦 + 一个可选学习层,每层只依赖局部信息:

```
┌─────────────────────────────────────────────────────┐
│ L4(可选) MARL 调参层:CTDE 训练,只调权重/计划,不做硬决策  │
├─────────────────────────────────────────────────────┤
│ L3 容断数据面:接触计划 + 束存储携带转发 + 超额预订管理      │  ← 源自 CGR
├─────────────────────────────────────────────────────┤
│ L2 路由计算面:分域分布式 Bellman-Ford + 能量状态机度量     │  ← 源自 DLER
├─────────────────────────────────────────────────────┤
│ L1 感知与拓扑维持面:信标 / SNR 剪枝 / 割点自识别 / 轮值休眠  │  ← 自身创新
└─────────────────────────────────────────────────────┘
```

设计哲学一句话:**连通性由 L1 的几何与调度机制保证(确定性、可证明),路径选择由 L2 的能量度量优化(分布式、收敛),数据完整性由 L3 的存储转发兜底(容忍分区),L4 只在不破坏前三层的地方学习。**

## 4. 各层机制详解

### 4.1 L1:邻居发现与链路准入

**信标(Hello)帧**,每 `T_b = 2s` 广播一次:

```
Hello = { node_id, seq, pos, SoC, queue_len, band_mask,
          domain_id, role, is_critical, neighbor_list(压缩) }
```

- `neighbor_list` 的作用:让邻居知道"我的邻居是谁",支撑 4.3 的割点自识别(2 跳视图)。
- SNR 由接收方被动测量,EWMA 平滑:`S ← (1-β)·S + β·S_meas`(β=0.3),消除巨石边缘的快衰落抖动。
- **链路准入双向确认**:i 认为 (i,j) 可用,当且仅当 ①EWMA-SNR ≥ γ_h(建链门限,比传输门限高 3 dB 留余量)②连续 3 个信标有效 ③j 的 Hello 里也含 i。任一不满足 → 不进拓扑图(宁绕远,不走悬崖边的链路——开题"信道感知拓扑"的去中心化版)。
- **链路失效判定**:连续 3 个 `T_b` 未收到 j 的 Hello → 判死,触发 L2 事件更新 + hold-down 计时器 `T_hold = 3·T_b`(防震荡/防乒乓)。

### 4.2 L1:结构感知的分域(划域)

CGR 综述明确指出其在大规模网络计算开销指数增长,方向之一就是"划域"。熔岩管天然帮我们划好了——**一个腔室 = 一个域**:

- 勘测地图先验划分:喉道两侧分属不同域,喉道中继即**边界节点(border)**。
- 每域推举一个**域锚(anchor)**:竞标函数 `w(i) = SoC_i × deg_i`,信标轮次内本域最大者自荐,域内确认。域锚不是簇头(CGR 综述批评的复杂簇头选举),只承担两件事:①汇总本域拓扑摘要;②域锚轮换(能量加权,避免锚先死)。
- 域内:平面结构(路艳玲选平面结构的理由同样成立——节点数少、安全性要求高)。
- 域间:边界节点交换"域摘要向量"(domain_id → 锚的代价),跨域路由按摘要走,信息不洪泛全网。

**规模感**:一管 5~10 个域,每域 6~15 节点,域内 Bellman-Ford 的收敛轮数和状态量都是常数级,彻底规避 CGR 的扩展性陷阱。

### 4.3 L1:割点自识别与冗余调度(本设计的核心创新点)

串珠状拓扑的命门在割点。全局求割点需要整张图,但有一个**纯局部的近似判据**:

> 节点 i 在自己的 2 跳图上检查:把 i 自己删掉,它的邻居们(通过 Hello 里的 `neighbor_list` 互相知晓)是否仍然连通?
> 不连通 → i 极大概率是全局割点(或关键中继)。

- 判定为 CRITICAL 的节点:①**永不休眠**;②发射功率提升 3 dB 维持备份链路;③向最近月球车发出"补位请求",请求其在附近驻留作为热备份。
- 非关键且互为邻居覆盖的冗余道钉:**轮值休眠**(PAMAS 思想的拓扑级扩展)。轮值表按域锚发布的种子确定,并**作为一条"接触计划"广播**——"道钉 #12 会在 t∈[t₁,t₂] 醒来,速率 X"。
- 由此得到一个关键设计闭环:**休眠调度本身就是接触计划的一部分**——节点睡了不是"消失",而是"定时回来的可预知接触"。这正是 CGR"可预知性是资源"思想在月面的落地。

### 4.4 L2:能量状态机式路由度量(承接 DLER)

对链路 (i→j),单跳代价(发射功率由链路预算反推,`physics.py` 已有):

```
c_ij = P_rx(j) + P_tx(i,j) + α          # α 为逐跳实时性罚项
```

节点能量三分态,决定它在路由中的"角色":

| 状态 | 条件 | 行为 |
|---|---|---|
| 正常 NORMAL | SoC ≥ 40% | 正常转发;选路最小化 `Σc_ij`(即总功耗 + 跳数罚) |
| 保护 PROTECTED | 20% ≤ SoC < 40% | 仍转发,但把自己到汇聚点的代价标成 ∞ 通告(**退出中继,只收不发别人的**) |
| 危急 DYING | SoC < 20% | 强制休眠保命,唤醒时刻写进接触计划 |

**度量切换**(DLER 的双模式):
- 若所有候选路径上的节点均 NORMAL → `min (Σc_ij + α·d)`(功耗/时延最优);
- 若某流量绕不开 PROTECTED 区 → 切换为 **max-min 剩余能量**选路(最大化路径上最弱点电量),把"谁还有多少血"放进度量。

**分布式计算(DSDV 式防环 Bellman-Ford)**:每节点维护 `{目的 → (代价, 下一跳, 序号)}`;序号单调递增,只接受更新序号的路由;拓扑变化触发增量更新而非周期全量。**实时控制指令**(急停/转向)走 DSR 式源路由 + 路由缓存:路径写进包头,中途不查表,一跳转发一跳校验,坏了立刻源端重算——用头开销换确定性时延。

### 4.5 L3:容断数据面(承接 CGR)

**触发**:距离向量里目的 d 消失超过 `T_wait = 3` 个更新周期 → 对 d 的流量进入束(bundle)模式。

**接触计划的四个来源**(全部是"可预知性",不需要发明任何新东西):
1. 月球车巡逻路线(勘测计划,最强先验);
2. 道钉轮值唤醒表(4.3 的副产物);
3. 地球可见窗口(地月链路定时通断——开题第 9 页的 DTN 需求);
4. 宇航员出舱活动计划。

**束转发决策(取 ECGR 改进的要点)**:
- 度量用**最早到达时刻**(单调 → 无环,规避原版 CGR 最早收回时刻的震荡问题);
- 发前检查接触**剩余容量**(速率 × 持续时间 − 已排队束),借鉴超额预订管理:不区分优先级地扣容量,避免低优先级束饿死;
- **关键束**(安全/急停指令)复制进所有可用下一跳的输出队列;普通束只进最优路径队列(镜像 CGR-FBP);
- 保管转移(custody):转发后不删本地副本,收到下游确认才删,防丢;
- 排队老化:超 TTL 自动降级丢弃(回答开题 Q&A 里"撑爆主节点"的问题)。

**接触异常处理**(CGR 最大的坑,综述 4.3:节点失效后数据包在死节点前堆积,投递率持续下跌):
- 预定接触窗口过了 `T_grace` 仍未建立链路 → 判定接触失效,**立即**向全域广播失效消息 + 本地重算次优路径 + 重新入队;
- 每节点每目的设队列上限(如 64 束),溢出时先丢最旧、最低优先级——用有损换不瘫。

### 4.6 故障处理全流程(L1→L2→L3 联动)

```
链路/节点死亡(3 信标超时)
  ├─ L1: 删边 → 2 跳图重算 → 新割点自识别/解除
  ├─ L2: 毒化路由 + 触发增量更新 + hold-down 防震荡
  │        └─ 3 轮内找到替代路径 → 恢复逐跳转发(自愈完成)
  └─ L2: 3 轮仍无路径 → 目的分区
           └─ L3: 转束模式,等接触计划窗口(车巡逻/道钉唤醒/地球升起)
                    └─ 窗口到达 → 携带转发/批量回传
```

## 5. 协议伪代码(节点 i 主循环)

```python
def node_loop(i):                                  # 每节点独立运行,无全局状态
    while True:
        # ---- L1:感知 ----
        if tick(T_b):                              # 信标周期
            broadcast(Hello(i))                    # 含邻居表/SoC/域号/关键位
            for j in timed_out_neighbors():         # 判死
                link_down(i, j)
        i.snr = ewma(i.snr, measure())              # 被动测量
        update_2hop_view()                          # 由收到的 Hello 拼装
        i.is_critical = is_cut_vertex_local(i)      # 删我后邻居是否散架
        schedule_sleep_or_awake(i)                   # 非关键道钉轮值

        # ---- L2:路由 ----
        if topology_changed() and not hold_down():
            for d in dest_table:                    # DSDV 增量更新
                relax(d, bellman_ford_local(i))     # 度量按能量状态机选(4.4)
            trigger_update(neighbors)
        if has_realtime_msg():                      # 控制指令
            src_route = cache.get(dst) or route_request()
            forward_along(src_route)                # 坏一跳即源端重算

        # ---- L3:容断 ----
        for d in unreachable(T_wait):               # 分区了
            bundle_queue.append(custody(msg, ttl, prio))
        for c in contacts.starting_now():           # 接触窗口开启
            if link_ok(c.peer):
                send_best_or_all(bundle_queue,       # 关键束全发,普通束最优
                                 metric="earliest_arrival",
                                 check="residual_capacity")
            elif missed(c):                          # 预定接触没出现
                broadcast_contact_invalid(c)         # CGR 的教训:立刻毒化
                requeue(bundle_queue)
```

## 6. 参数表(初值,全部进仿真扫描)

| 参数 | 初值 | 说明 |
|---|---|---|
| `T_b` | 2 s | 信标周期 |
| `T_fail` | 3×T_b | 邻居判死 |
| `T_hold` | 3×T_b | 路由震荡抑制 |
| `γ_h` | 链路门限+3 dB | 建链 SNR 余量 |
| β | 0.3 | SNR EWMA 平滑 |
| `E_protect` / `E_die` | 40% / 20% | 能量状态机阈值(DLER 取 40%,工程上调) |
| α | 单跳功耗的 ~10% | 实时性罚项 |
| `T_wait` | 3 更新周期 | 进入束模式判定 |
| 队列上限 | 64 束/目的 | 溢出丢旧丢低优 |

## 7. L4:MARL 融合路线(可选升级,防"为学习而学习")

**架构原则:协议兜底,学习调参。** L1~L3 是确定性安全网,保证最差情况下网络仍按可证明的规则运行;RL 不直接决定"数据发给谁"这类安全攸关动作,而是调三类参数:

| 学习动作 | 状态观测(局部) | 奖励(团队共享) |
|---|---|---|
| ① 度量权重 α/能量阈值的动态调节 | 自身 SoC、各邻居 SNR、队列、2 跳摘要 | `w1·交付率 − w2·能耗 − w3·时延 − w4·丢包` |
| ② 道钉轮值休眠表的编排 | 邻居互覆盖矩阵 | 同上 + 网络生存时间(首节点死亡时间,路艳玲的指标) |
| ③ 月球车补位/巡逻路径建议 | 分区检测事件、割点分布 | 恢复时间 + 覆盖率 |

- 算法:**QMIX 值分解**(单调性约束 `∂Q_tot/∂Q_ind ≥ 0` 保证去中心化执行时个体贪婪即全局最优);连续动作(功率/路径)用 MAPPO。
- 训练环境:**现有仿真沙盘直接改造成 PettingZoo 风格多智能体环境**——这正呼应李勐文中所说"构建高保真数字孪生,为策略部署提供验证"。
- 非平稳对策:灾害注入(塌方/热浪/耀斑)作为课程化变体,元学习提升迁移;离线训练 + 在沙盘回放验证后再上"策略白名单"(李勐提出的策略安全验证瓶颈,我们用"RL 只调参"从架构上绕开)。

## 8. 落地到现有代码的实施路径

现状:`engine.compute_network()` 是全局 Dijkstra 上帝视角。分四步渐进改造,**每步结束沙盘都可运行、可演示**:

1. **Step 1(去中心化地基)**:把全局图拆成每节点局部视图(只含准入链路),实现 DSDV 式迭代 Bellman-Ford,能量状态机度量替换 `link_cost`。验证:无灾害时与全局 Dijkstra 结果一致(收敛性);灾害时恢复时间。
2. **Step 2(结构韧性)**:Hello/2 跳视图/割点自识别/轮值休眠;沙盘 UI 给割点打标记(很直观的演示点:拖走一块巨石,喉道割点亮红,月球车自动补位)。
3. **Step 3(容断)**:束模式 + 接触计划(车巡逻表/唤醒表/地球窗口),EventLog 播报"网络分区,数据进入携带转发模式…"。加一个"分区修复时间"HUD 指标。
4. **Step 4(学习层,时间富余才做)**:沙盘包环境,QMIX 调三类参数,对比"手调参数 vs 学习参数"的生存时间曲线。

## 9. 验证指标与实验设计(对齐开题承诺)

| 指标 | 定义 | 对照 |
|---|---|---|
| 抗毁性 | 30% 节点失效后核心数据不断联(开题量化承诺) | 随机杀伤 + 定向杀伤(专打割点)两套 |
| 覆盖率恢复时间 | 灾害 → 覆盖率回升至 95% 的秒数 | 全局 Dijkstra(性能上界)vs LTRP vs 纯 DSR 最小跳 |
| 网络生存时间 | 首节点能量死亡时刻(路艳玲的核心指标) | vs DSR / MMBCR / LTRP |
| 束交付率/时延 | 分区场景下束的最终送达率(徐双的评估方法) | vs 存储-不转发(纯等待) |
| 控制开销 | Hello+更新的字节占比 | 域划 vs 全网洪泛 |

预期卖点叙事(答辩用):**"普通算法只看几何和跳数;我们把能量状态机、接触计划、割点自识别全部做进了每个节点的两公里视野之内——没有上帝视角,照样自愈。"**
